# 012.3 — Programmatic Tool Calling

**Status:** Ready  
**Estimated effort:** ~2-3 hours  
**Branch:** `feat/012.3-programmatic-tool-calling`

## Motivation

Nous currently calls memory tools one at a time — each `recall_deep` or `recall_recent`
invocation is a separate model round-trip. For multi-recall workflows (e.g. "what do I know
about X across facts, decisions, and recent episodes?"), this means 3+ round-trips through
the model before Claude has the information it needs.

Anthropic's `code_execution_20260120` tool allows Claude to write Python code that calls
tools programmatically in a sandbox. Instead of:

```
turn 1: recall_deep("facts about X") → model → result
turn 2: recall_recent() → model → result  
turn 3: recall_deep("decisions about X") → model → result
turn 4: synthesize and respond
```

Claude can write a script, run all three lookups in one shot, filter the results, and
return only the relevant slice to reason over:

```
turn 1: code_execution script calls all 3 tools, filters results → model synthesizes → respond
```

Anthropic benchmarks (BrowseComp, DeepSearchQA) show this is the single biggest
unlock for multi-step agent performance.

## Scope

Minimal, surgical change. Three parts:

1. **Add `code_execution_20260120` tool** to the tools payload
2. **Mark read-only tools** with `allowed_callers` 
3. **Handle code execution result blocks** in the runner tool loop

No new DB tables. No schema changes. Feature-flagged via config.

## Read-Only Tools (safe to expose to code execution)

| Tool | Why safe |
|------|----------|
| `recall_deep` | Pure read — queries Brain + Heart, no writes |
| `recall_recent` | Pure read — queries Heart episodes, no writes |

**Explicitly NOT exposed** (side effects):
- `record_decision` — writes to Brain
- `learn_fact` — writes to Heart
- `create_censor` — writes to Heart
- All subtask tools — external effects

## Implementation

### Part 1: Config flag

`nous/config.py` — add one setting:

```python
programmatic_tools_enabled: bool = Field(
    default=False,
    description="Enable code_execution_20260120 for programmatic tool calling (beta)",
)
```

Env var: `NOUS_PROGRAMMATIC_TOOLS_ENABLED=true`

### Part 2: Tool registration (`nous/api/tools.py`)

Add `allowed_callers` to the two read-only tool schemas:

```python
# In _RECALL_DEEP_SCHEMA
_RECALL_DEEP_SCHEMA: dict[str, Any] = {
    "type": "object",
    ...
    "allowed_callers": ["code_execution_20260120"],  # ADD THIS
}

# In _RECALL_RECENT_SCHEMA  
_RECALL_RECENT_SCHEMA: dict[str, Any] = {
    "type": "object",
    ...
    "allowed_callers": ["code_execution_20260120"],  # ADD THIS
}
```

### Part 3: Inject code_execution tool (`nous/api/runner.py`)

In `ToolDispatcher.available_tools()` (or wherever tools are assembled for the API payload),
prepend the code execution tool when the feature flag is on:

```python
def available_tools(self, frame_id: str) -> list[dict[str, Any]]:
    tools = [...]  # existing logic
    if self._settings.programmatic_tools_enabled:
        tools = [{"type": "code_execution_20260120", "name": "code_execution"}] + tools
    return tools
```

### Part 4: Handle code execution blocks in tool loop (`nous/api/runner.py`)

The runner's streaming tool loop currently only handles `tool_use` blocks. Code execution
emits different event types that need to be passed through. In the streaming loop, add
handling for `code_execution_input`, `code_execution_output` block types:

```python
elif event.type == "content_block_start":
    block = event.content_block
    if block.get("type") == "code_execution_input":
        # Claude is writing a tool script — log for debug, no action needed
        logger.debug("Code execution script started")
    elif block.get("type") == "code_execution_result":
        # Script ran — results are automatically fed back to Claude
        # Log for observability
        logger.debug("Code execution result received")
```

The Anthropic SDK handles the sandbox execution and result injection automatically —
Nous doesn't need to run the sandbox itself. The SDK executes the script, calls our
registered tools (via `allowed_callers`), and returns results in the message stream.

## What Changes

```
nous/config.py              +1 setting (programmatic_tools_enabled)
nous/api/tools.py           +2 lines (allowed_callers on 2 schemas)
nous/api/runner.py          +~15 lines (inject tool + handle new block types)
```

No DB migrations. No new dependencies. Fully backward-compatible (feature off by default).

## Rollout

- Default: off (`NOUS_PROGRAMMATIC_TOOLS_ENABLED=false`)
- Enable in `.env` to test
- Monitor: watch for unexpected code execution errors in logs
- If stable, consider enabling by default in a follow-up
