# 012.3 — Programmatic Tool Calling (Client-Side Execution)

**Status:** Ready  
**Estimated effort:** ~3-4 hours  
**Branch:** `feat/012.3-programmatic-tool-calling`

## Motivation

**Primary goal: reduce token consumption and model round-trips.**

Nous currently calls memory tools one at a time — each `recall_deep` or `recall_recent`
is a separate model round-trip, and every result lands in the context window raw. For a
query spanning facts, decisions, and episodes, Claude sees 3 full tool results before it
can synthesize a response. Most of that data is noise.

**client-side direct execution** flips this: Claude gets a `run_python` tool and writes
a script that fetches, filters, and shapes memory data before it enters context. Instead
of 10 raw facts bloating the prompt, Claude returns the 3 relevant ones.

```python
# Claude writes this in one tool call:
facts = recall_deep("caching strategy", limit=10)
recent = recall_recent(hours=24)
# Filter and shape BEFORE returning to context
hits = sorted([f for f in facts if f["score"] > 0.6],
              key=lambda f: f["confidence"], reverse=True)[:3]
result = json.dumps({"top_facts": hits, "recent": recent[:2]})
```

One tool call. Filtered output. Claude reasons over 3 facts instead of 10.
Token savings compound across multi-step recall workflows.

We use client-side execution (not Anthropic's hosted `code_execution_20260120` sandbox)
for full control, no model version constraints, and no dependency on unverified
`allowed_callers` callback behavior.

## Advantages Over Anthropic-Native Approach

- **No `allowed_callers` complexity** — it's a standard `tool_use` block
- **No streaming block type changes** — existing tool loop handles it unchanged
- **No model compatibility constraints** — works with any model Nous supports
- **Full safety control** — restricted builtins, timeout, write caps enforced server-side
- **Frame-gated exactly like any other tool** — plugs into `FRAME_TOOLS` cleanly
- **No Anthropic sandbox availability risk** — runs in-process

## Scope

Three parts:

1. **`run_python` tool** — new tool in `tools.py`
2. **Execution environment** — sync wrappers around Brain/Heart, restricted builtins, timeout
3. **Frame registration** — add `run_python` to appropriate frames in `FRAME_TOOLS`

No new DB tables. No schema changes. Feature-flagged via config.

## Execution Environment

The code runs via `exec()` in a thread pool (required because Brain/Heart are async; thread
allows `asyncio.run()` for each sync wrapper without conflicting with the main event loop).

### Functions available in scope

| Function | Maps to | Writes? | Cap |
|----------|---------|---------|-----|
| `recall_deep(query, limit=5)` | `heart.search_facts()` + `brain.query()` | No | — |
| `recall_recent(hours=24, limit=5)` | `heart.list_episodes()` | No | — |
| `list_tasks(status=None)` | `heart.list_subtasks()` | No | — |
| `learn_fact(content, category, subject=None, confidence=1.0)` | `heart.store_fact()` | Yes | 5 per execution |

Write cap: a counter in the execution context increments on each `learn_fact` call and
raises `RuntimeError("write cap exceeded")` after 5. Prevents runaway bulk writes.

### Stdlib modules (whitelisted)

Pure-computation modules are pre-imported and available in the execution namespace.
These let Claude shape and filter recalled data before returning it — reducing what
the model has to reason over, which directly cuts token consumption.

```python
import json, re, math, datetime, collections, itertools, functools, statistics

SAFE_MODULES = {
    "json":        json,        # parse/format structured data
    "re":          re,          # regex on fact content
    "math":        math,        # numeric analysis
    "datetime":    datetime,    # time arithmetic on episode timestamps
    "collections": collections, # Counter, defaultdict for aggregation
    "itertools":   itertools,   # groupby, chain, islice for data shaping
    "functools":   functools,   # reduce, partial
    "statistics":  statistics,  # mean, median for confidence analysis
}
```

Example — return only the 3 highest-confidence facts about a topic:
```python
facts = recall_deep("caching", limit=10)
top = sorted(facts, key=lambda f: f["confidence"], reverse=True)[:3]
result = json.dumps(top)
```

Without this, Claude would receive all 10 facts into context, reason over them,
and output the filtered 3 — burning tokens on the raw data. With `run_python`,
the model only sees the final 3.

**Blocked regardless:** `open`, `os`, `subprocess`, `socket`, `importlib`,
`sys`, `eval`, `exec`, `__import__`. The `import` statement is disabled in
the exec namespace — modules are injected directly, not importable.

### Restricted builtins

```python
SAFE_BUILTINS = {
    "len", "list", "dict", "set", "str", "int", "float", "bool",
    "print", "range", "enumerate", "zip", "sorted", "filter",
    "map", "max", "min", "sum", "any", "all", "isinstance",
    "repr", "round", "abs", "type", "tuple",
}
```

### Timeout

Configurable. Default 10 seconds. Enforced via `concurrent.futures.ThreadPoolExecutor` with `future.result(timeout=settings.programmatic_tools_timeout)`.

### Part 2: `run_python` tool (`nous/api/tools.py`)

Add to `create_nous_tools()`:

```python
async def run_python(code: str) -> dict[str, Any]:
    """Execute Python code with Nous memory functions in scope.

    Returns stdout output + result variable if set.
    """
    import asyncio
    import io
    import concurrent.futures

    write_count = {"n": 0}
    MAX_WRITES = 5
    output_buf = io.StringIO()

    # Sync wrappers (run in thread pool, so asyncio.run() is safe)
    def _recall_deep(query: str, limit: int = 5) -> list:
        return asyncio.run(heart.search_facts(query, limit=limit))

    def _recall_recent(hours: int = 24, limit: int = 5) -> list:
        return asyncio.run(heart.list_episodes(limit=limit, hours=hours))

    def _list_tasks(status: str | None = None) -> list:
        return asyncio.run(heart.list_subtasks(status=status))

    def _learn_fact(
        content: str,
        category: str = "technical",
        subject: str | None = None,
        confidence: float = 1.0,
    ) -> str:
        if write_count["n"] >= MAX_WRITES:
            raise RuntimeError(f"learn_fact write cap ({MAX_WRITES}) exceeded")
        write_count["n"] += 1
        asyncio.run(heart.store_fact(FactInput(
            content=content, category=category,
            subject=subject, confidence=confidence,
        )))
        return f"stored: {content[:60]}"

    def _print(*args):
        output_buf.write(" ".join(str(a) for a in args) + "\n")

    safe_builtins = {k: getattr(__builtins__, k, None) or __builtins__[k]
                     for k in SAFE_BUILTINS if hasattr(__builtins__, k)}

    import json as _json, re as _re, math as _math
    import datetime as _datetime, collections as _collections
    import itertools as _itertools, functools as _functools
    import statistics as _statistics

    namespace = {
        "__builtins__": safe_builtins,
        # Nous memory functions
        "recall_deep": _recall_deep,
        "recall_recent": _recall_recent,
        "list_tasks": _list_tasks,
        "learn_fact": _learn_fact,
        "print": _print,
        "result": None,
        # Safe stdlib modules (pre-injected — import statement is disabled)
        "json": _json,
        "re": _re,
        "math": _math,
        "datetime": _datetime,
        "collections": _collections,
        "itertools": _itertools,
        "functools": _functools,
        "statistics": _statistics,
    }

    def _run():
        exec(compile(code, "<nous_script>", "exec"), namespace)

    _timeout = settings.programmatic_tools_timeout
    try:
        with concurrent.futures.ThreadPoolExecutor(max_workers=1) as executor:
            future = executor.submit(_run)
            future.result(timeout=_timeout)
    except concurrent.futures.TimeoutError:
        return {"content": [{"type": "text", "text": f"Error: execution timed out ({_timeout}s)"}]}
    except Exception as e:
        return {"content": [{"type": "text", "text": f"Error: {type(e).__name__}: {e}"}]}

    output = output_buf.getvalue()
    result = namespace.get("result")
    text = output or (str(result) if result is not None else "OK")
    return {"content": [{"type": "text", "text": text}]}
```

Schema:

```python
_RUN_PYTHON_SCHEMA: dict[str, Any] = {
    "type": "object",
    "description": (
        "Execute Python code with Nous memory functions and safe stdlib in scope. "
        "Memory functions: recall_deep(query, limit=5), recall_recent(hours=24, limit=5), "
        "list_tasks(), learn_fact(content, category, subject, confidence). "
        "Stdlib available: json, re, math, datetime, collections, itertools, functools, statistics. "
        "Use this to batch multiple memory lookups, filter results, and return only what's needed — "
        "reducing token usage compared to separate tool calls. "
        "Set result = <value> to return structured data. Use print() to emit text output. "
        "Max runtime is configurable (default 10s). Max 5 learn_fact calls per execution."
    ),
    "properties": {
        "code": {
            "type": "string",
            "description": "Python code to execute",
        }
    },
    "required": ["code"],
}
```

Register conditionally in `register_nous_tools()`:

```python
if settings.programmatic_tools_enabled:
    dispatcher.register("run_python", closures["run_python"], _RUN_PYTHON_SCHEMA)
```

### Part 3: Frame registration (`nous/api/runner.py`)

Add `run_python` to frames where multi-recall batching is valuable:

```python
FRAME_TOOLS: dict[str, list[str]] = {
    "conversation": [..., "run_python"],
    "question":     [..., "run_python"],
    "task":         ["*"],  # already includes all
    "debug":        [..., "run_python"],
    "decision":     [...],          # no — decisions need deliberate tool use
    "creative":     [...],          # no — no recall batching needed
    "initiation":   [...],          # no — constrained setup flow
}
```

## What Changes

```
nous/config.py      +2 settings (programmatic_tools_enabled, programmatic_tools_timeout)
nous/api/tools.py   +~70 lines (run_python closure + schema + conditional register)
nous/api/runner.py  +4 lines (run_python in FRAME_TOOLS entries)
```

All stdlib modules (`json`, `re`, `math`, `datetime`, `collections`, `itertools`,
`functools`, `statistics`) are already in Python's stdlib — no new pip dependencies.

No DB migrations. No new dependencies. Subtask worker gets it for free (same runner).

## Subtask Behavior

Subtask workers run through the same runner — `run_python` is available in `task` frame
automatically. Greatest benefit for research subtasks that batch multiple recall queries
before synthesizing a result.

## Episode Summarizer / Fact Extractor

These handlers (`episode_summarizer.py`, `fact_extractor.py`, `knowledge_extractor.py`)
bypass the runner entirely (direct httpx calls → parse JSON → write to Heart). They don't
benefit from `run_python` in this release. Tracked as future refactor: migrate to subtask
runner so they can use programmatic recall + dedup-before-store.

## Rollout

- Default: off
- Enable with `NOUS_PROGRAMMATIC_TOOLS_ENABLED=true` in `.env`
- Monitor logs for `RuntimeError`, timeout, or `SyntaxError` in `run_python` calls
- If stable after 1 week of use, consider enabling by default
