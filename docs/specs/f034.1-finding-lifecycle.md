# F034.1 — Finding Lifecycle Management

**Status:** PROPOSED  
**Priority:** P1 (immediate — prerequisite for F034.2, F034.3)  
**Depends on:** F034 Heartbeat (merged)  
**Author:** Nous + Tim  
**Date:** 2026-04-03  

## Problem

Heartbeat checks run on fixed intervals and report findings each time. If HealthCheck
finds 5 stale decisions, it re-reports them every hour — 24 duplicate triage sessions per
day. There's also no mechanism for findings to escalate if they go unaddressed.

## Goals

1. **Deduplicate findings** — same finding reported once, not on every tick
2. **Track finding state** — new → acknowledged → resolved
3. **Escalate unaddressed findings** — normal → high after configurable duration
4. **Provide a daily digest** for acknowledged-but-unresolved findings (instead of hourly noise)

## Design

### 4.1 Finding Identity

Each finding gets a **fingerprint** — a stable hash derived from:
```
fingerprint = sha256(check_name + category + description_normalized)
```

`description_normalized` strips volatile parts (timestamps, counts) and keeps the
structural identity. Each check can override `fingerprint_key()` to control what
makes a finding "the same."

Example: "5 unreviewed decisions older than 7 days" and "7 unreviewed decisions older
than 7 days" should have the SAME fingerprint (the issue is "stale decisions", not the
count).

### 4.2 Finding State Machine

```
  ┌──────────┐    auto (dedup)     ┌──────────────┐
  │   new     │ ──────────────────► │  suppressed   │
  └──────────┘                     └──────────────┘
       │                                  │
       │  cognitive triage                │ TTL expires
       ▼                                  ▼
  ┌──────────────┐                 ┌──────────┐
  │ acknowledged  │                │   new     │  (re-surfaces)
  └──────────────┘                 └──────────┘
       │
       │  resolved by action / manual
       ▼
  ┌──────────┐
  │ resolved  │
  └──────────┘
```

**States:**
- `new` — First time seen. Triggers full triage (Telegram or cognitive session).
- `suppressed` — Duplicate of an existing finding. Silently dropped. Has a TTL.
- `acknowledged` — Triage ran, but finding is not yet resolved. Appears in daily digest only.
- `resolved` — Finding no longer active. Kept for 7 days for audit, then pruned.

### 4.3 Finding Store

In-memory dict with persistence to Heart facts (so findings survive restarts):

```python
class FindingStore:
    """Tracks finding lifecycle."""
    
    def __init__(self):
        self._findings: dict[str, TrackedFinding] = {}  # fingerprint → finding
    
    def ingest(self, finding: Finding) -> FindingAction:
        """Returns: TRIAGE | SUPPRESS | ESCALATE"""
        fp = finding.fingerprint()
        
        if fp in self._findings:
            existing = self._findings[fp]
            if existing.state == "resolved":
                # Re-opened — treat as new
                existing.reopen()
                return FindingAction.TRIAGE
            
            existing.bump_count()
            
            # Escalation check
            if existing.should_escalate():
                existing.escalate()
                return FindingAction.ESCALATE
            
            return FindingAction.SUPPRESS
        
        # Brand new finding
        self._findings[fp] = TrackedFinding(finding)
        return FindingAction.TRIAGE
    
    def acknowledge(self, fingerprint: str):
        """Mark as seen by triage. Moves to daily digest."""
        self._findings[fingerprint].state = "acknowledged"
    
    def resolve(self, fingerprint: str):
        """Mark as resolved."""
        self._findings[fingerprint].state = "resolved"
        self._findings[fingerprint].resolved_at = datetime.utcnow()
    
    def get_digest_items(self) -> list[TrackedFinding]:
        """All acknowledged but unresolved findings for daily digest."""
        return [f for f in self._findings.values() if f.state == "acknowledged"]
```

### 4.4 Escalation Policy

Default escalation rules (configurable via REST API):

| Original Urgency | Escalates To | After         |
|-------------------|-------------|---------------|
| low               | normal      | 72 hours      |
| normal            | high        | 24 hours      |
| high              | high (re-alert) | 12 hours  |

**Accumulation escalation:** If 5+ findings from the same check are all acknowledged/unresolved, 
the *collection* escalates one level regardless of individual age.

### 4.5 Daily Digest

A new check (or runner behavior) that fires once per day (configurable, default 09:00 local):

- Collects all `acknowledged` findings
- Groups by check name
- Sends a single Telegram summary:
  ```
  🫀 Daily Heartbeat Digest
  
  HealthCheck (3 items):
  • 5 unreviewed decisions (3 days old) ⬆️ escalating tomorrow
  • 12 stale facts 
  • procedure "old-skill" at 40% effectiveness
  
  SelfInitiatedCheck (1 item):
  • Pending: research context pruning papers
  ```
- Findings that will escalate soon get a ⬆️ warning

### 4.6 REST API Extensions

- `GET /heartbeat/findings` — All tracked findings with state/age
- `POST /heartbeat/findings/{fingerprint}/acknowledge` — Manual acknowledge
- `POST /heartbeat/findings/{fingerprint}/resolve` — Manual resolve
- `PUT /heartbeat/escalation-policy` — Update escalation thresholds

### 4.7 Integration with Runner

Modify `HeartbeatRunner._triage_findings()`:

```python
async def _triage_findings(self, findings: list[Finding]):
    for finding in sorted(findings, key=lambda f: f.urgency, reverse=True):
        action = self._finding_store.ingest(finding)
        
        if action == FindingAction.SUPPRESS:
            continue  # Already known, skip
        
        if action == FindingAction.ESCALATE:
            finding.urgency = "high"  # Upgraded
        
        # Existing triage logic (Telegram for high, cognitive for normal)
        if finding.urgency == "high":
            await self._send_telegram_alert(finding)
        elif finding.actionable:
            await self._cognitive_triage(finding)
        
        # Mark as acknowledged after triage
        self._finding_store.acknowledge(finding.fingerprint())
```

## Risks

- **Fingerprint collisions** — Two genuinely different findings hash the same. Mitigated by 
  letting checks override `fingerprint_key()`.
- **Over-suppression** — Aggressive dedup might hide a finding that changed character. 
  Mitigated by TTL on suppression (re-surfaces after expiry).
- **Persistence** — In-memory store is lost on restart. Phase 1 can accept this (findings 
  regenerate on next check run). Phase 2 should persist to DB.
